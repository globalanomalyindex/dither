# DITHER Program Roadmap

## Governing direction

DITHER remains a static, client-side, local-first creative workshop. The program introduces professional development tooling and selective modern boundaries without rewriting protected creative engines for fashion or novelty.

The product is optimized as a real tool first. Repository quality, documentation, demonstrations, and a reviewer-facing case study make its reasoning inspectable.

## Branch sequence

1. `agent/dither-00-verification-foundation`
2. `agent/dither-01-document-render-boundaries`
3. `agent/dither-02-history-checkpoints-persistence`
4. `agent/dither-03-workspace-onboarding`
5. `agent/dither-04-creative-stages`
6. `agent/dither-05-compare-bake-export`
7. `agent/dither-06-visual-accessibility-responsive`
8. `agent/dither-07-hardening-case-study-release`

Each plan starts from the reviewed result of the preceding plan. Product-model changes do not begin until Plan 0 verification is accepted.

## Plan 0: Verification foundation

- portable setup
- pinned development dependencies and lockfile
- deterministic static build
- CI jobs for contracts, toolchain, browser smoke, and evidence artifacts
- initial privacy and runtime characterization
- durable audit, risk, decision, claims, provenance, and release records

## Plan 1: Document and render boundaries

- define one document model
- isolate commands, selections, stages, and render requests
- establish deterministic engine fixtures before extraction
- move high-value seams to TypeScript and modules

## Plan 2: History, checkpoints, and persistence

- unify parameter, paint, checkpoint, reset, and recovery semantics
- make Bake a named checkpoint rather than an opaque destructive action
- define bounded persistence and crash recovery

## Plan 3: Workspace and onboarding

- dual entry through import and one curated editable sample
- clarify first successful creative path
- establish stage list, canvas, and inspector shell
- preserve advanced capability through progressive disclosure

## Plan 4: Creative stages

- express Dither, Grain, and Paint as recognizable stage types
- support ordering, selection, visibility, and context
- make interaction consequences legible

## Plan 5: Compare, Bake, and export

- original, checkpoint, and current comparison
- production-check export
- explicit output size, alpha, format, and expected limitations

## Plan 6: Visual, accessibility, and responsive polish

- Standard shell, Quiet controls, Exhibition canvas
- semantic signal color and disciplined typography
- unified focus, reduced motion, zoom, keyboard, and screen-reader behavior
- intentional supported viewport tiers

## Plan 7: Hardening, case study, and release

- performance budgets and large-image behavior
- browser and input matrix
- license and contribution posture
- complete provenance and claims evidence
- reviewer-facing case study based on verified work

## Program gates

- no unprotected engine rewrite
- no hidden remote runtime dependency
- no decorative technical density
- no generated product evidence
- no broad accessibility or production claim without supporting tests
- no plan merge while its required verification matrix rows are red
